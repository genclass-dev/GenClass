POLICY GATE (read first): Audiobookshelf does not accept or review PRs or issues that are fully AI-generated. The sender must reproduce by hand and write the issue and PR body in their own words; hand back facts, the reproduction, the fix and the test, and notes for the sender instead of paste-ready prose. Keep any fix to one small change (first-time contributors are asked for small PRs).

Where the notes below differ from the policy gate above (for example a fix patch or PR text), the gate wins.

Why: Two OPEN race reports already describe GenClass's bug class: #2231 'Match has a slow race condition with user input' (open since 2023-10-21, 16 comments, still reproduced 2024-02-28: after a Match, the edit-book modal accepts user edits that are then wiped when the late 'item updated' update lands) and #5627 (2026-10-01, labelled bug: a stale, unclosed playback session overwrites newer progress on close). The app runs natively as one Node process on SQLite with no external service, so a hunt reproduces #2231 without GenClass, explores the Match/edit and progress-sync orders, and fixes the client (socket item_updated vs. modal state) with a regression test. Media category, 14.9k stars.

What to contribute: docs/adoption/hunts/audiobookshelf.md (report with the explore numbers and the false-report rate on the fixed build), a patch to client/ (edit-item modal and socket item_updated handling, plus the progress-close comparison in server/ if #5627 reproduces) with a regression test in the project's style, an issue draft (or comment on #2231) and a PR draft with AI-assistance disclosure.
