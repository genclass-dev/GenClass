Why: Largest document-management SPA in the category (47.6k stars) whose closed issues already show the stale-UI class (#13765 stale permission checkmark shown client-side until Save; #14306 document content stale in the web UI after reprocessing). The document list combines full-text search-as-you-type with many filters and paging, the detail page saves edits with autocompletes, and WebSocket status messages trigger refreshes: good explore targets. Everything runs natively (uv, Redis from apt, SQLite). Caveat: AI use must be disclosed, the fix must not be mostly AI-derived, and issue reports must state observed behaviour only.

What to contribute: docs/adoption/hunts/paperless-ngx.md, a patch to src-ui/src/app (switchMap/sequence guard in the affected service or component) with a Jasmine spec, an issue draft limited to observed behaviour and reproduction steps, and a PR draft (target dev) with the AI disclosure the project requires.

Mechanism: Issue via the bug template, then a PR to paperless-ngx/paperless-ngx targeting `dev` (bug fixes welcome; feature PRs need an existing feature request); review by the frontend team: https://github.com/paperless-ngx/paperless-ngx/blob/dev/CONTRIBUTING.md

Stack: Backend: Django (Python 3.11-3.14, uv), SQLite by default (PAPERLESS_DBENGINE defaults to sqlite, data/db.sqlite3), Redis/Valkey broker for Celery. Frontend: Angular 22 + rxjs 7 in src-ui (environment.ts apiBaseUrl http://localhost:8000/api/, webSocketHost localhost:8000).
