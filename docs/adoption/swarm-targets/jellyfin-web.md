# Jellyfin Web

Session brief for the adoption swarm (docs/adoption/swarm.md), 2026-11-03. Slug `jellyfin-web`, type hunt.

TARGET: Jellyfin Web (jellyfin/jellyfin-web). TYPE: hunt (`docs/adoption/swarm.md` section 4.1). SLUG: jellyfin-web.

POLICY GATE (read first): Jellyfin bans LLM-written prose in issues, PRs and review replies, and LLM code only with disclosure in the template's "Code assistance" section and never as the sole source of the change. So hand back facts (steps, the measured timeline, the replay order, test output) and a reference fix for a person to rewrite and own, never paste-ready issue or PR text. Quote the policy in the report.

Where the notes below differ from the policy gate above (for example a fix patch or PR text), the gate wins.

Why: The most-used self-hosted media UI, with an open duplicate-request bug (#8277 'Details/items using two requests for the same payload', 2026-07-30, labelled bug) and classic surfaces: search-as-you-type, library views with filters/sort/paging, playback progress reporting, favorite/played toggles, dashboard forms. Both halves run natively (dotnet 10 SDK, ffmpeg from apt). Policy allows LLM-assisted code but every issue, comment and PR body must be written by the contributor, and the PR template must be fully completed.

What to contribute: docs/adoption/hunts/jellyfin-web.md, a patch to jellyfin-web/src (react-query keys/dedupe or the legacy fetch path behind #8277) with a Vitest test, an issue draft written in the contributor's own words (or a comment on #8277), and a PR draft that follows the template, split into small commits, with no LLM metafiles.

Mechanism: PR to jellyfin/jellyfin-web (master) per CONTRIBUTING.md (unit tests when possible, full PR template, LLM policy): https://github.com/jellyfin/jellyfin-web/blob/master/CONTRIBUTING.md; policy: https://jellyfin.org/docs/general/contributing/llm-policies

Stack: Frontend: jellyfin-web, React 18 + @tanstack/react-query 5 + axios + react-router 6 over a legacy JS 'Emby WebComponents' app; webpack dev server (`npm start`, no proxy: the client connects to a server URL). Server: jellyfin/jellyfin, .NET 10 + ffmpeg, SQLite.

Verifier's verdict (primary sources read 2026-11-03; re-check anything you rely on): Real, active (pushed 2026-11-02, GPL-2.0, 3,960 stars; server 58,956), with a documented native run path (server README: `dotnet run --project Jellyfin.Server --webdir <jellyfin-web/dist>`; faster: the apt repo's `unstable` component ships a self-contained server build matching web master 13.0.0, no Docker). Policy permits LLM-assisted code with disclosure in the PR template's "Code assistance" section, and maintainers themselves disclose Claude use (#8719); but LLM prose is banned, so the owner must write the issue and PR body himself and be able to explain and defend the patch. Three or more fetch-driven surfaces with no stale-response guards exist in the legacy views. Go, with the conditions in riskNotes; welcome is moderate (two team reviews, slow community turnaround).

Verifier's notes for this target: Pair jellyfin-web master (package.json version 13.0.0) with a master-tracking server: the apt repo's `unstable` component (jellyfin-server 2026110213, self-contained, no .NET SDK) or the README's documented `dotnet run --project Jellyfin.Server --webdir <dist>` with the .NET 10 SDK (global.json 10.0.0). The stable server is 12.4.0 and may lack endpoints the unstable SDK (`@jellyfin/sdk@0.0.0-unstable.202610291827`) calls. Install Node 24 first: `.npmrc` sets `engine-strict=true` and `engines` demands node>=24/npm>=11, so npm on Node 22 exits with EBADENGINE (reproduced locally). No default login: the first-run wizard at http://127.0.0.1:8096/web/ creates the admin; add a Movies library of VP9/Opus webm files (Playwright's Chromium has no H.264). Inject the runtime with `page.addInitScript` or a `page.route` on the served HTML, observe mode, no source change.

Tests: Vitest 3.2.7 with jsdom (`npm test`), colocated as `src/**/*.test.ts` (model: `src/lib/jellyfin-apiclient/utils/getItems.test.ts`, merged 2026-10-28). No @testing-library, no react-test-renderer, no Playwright: the regression test must exercise a pure module or a jsdom-level unit. CONTRIBUTING deems legacy component/view code untestable, requires new files in TypeScript and API calls through the SDK, forbids Conventional Commits.

Surfaces, best first: favorite/played double toggle (`src/elements/emby-ratingbutton/emby-ratingbutton.js` writes state from the response and from the WebSocket `UserDataChanged`; `FavoriteButton.tsx` + `useToggleFavorite.ts` derive `isFavorite` from props then `invalidateQueries`); legacy library sort/filter changes (`src/apps/legacy/controllers/list.js` `fetchData` renders whichever response arrives, `isLoading` only guards paging; `controllers/movies/movies.js` same pattern); details navigation (`controllers/itemDetails/index.js`: `getItem` then similar/episodes/lyrics fetches with no view-generation check; #8277's duplicate item request); search typing (`features/search/api/useSearchItems.ts`); playback progress vs stop (`components/playback/playbackmanager.js` `sendProgressUpdate` / `reportPlaybackStopped`).
