POLICY GATE (read first): ntfy's docs/ai-policy.md welcomes AI-assisted PRs only when a human reviewed, understood and tested them, with human-written or human-edited issue and PR text. Mark every draft as text the sender must rewrite in their own words.

Where the notes below differ from the policy gate above (for example a fix patch or PR text), the gate wins.

Why: The web app deliberately merges two delivery paths per subscription, a since-poll (Poller.js) and a WebSocket stream (Connection.js), into IndexedDB, and syncs account settings and subscriptions through AccountApi.js: duplicate, out-of-order and stale-write cases are the design's own edge. The repo ships a Playwright harness (`make web-e2e`: builds build/ntfy-e2e, starts a real server on 127.0.0.1:12586 with a throwaway database in build/e2e/, 56 passing specs) that a hunt can reuse to inject the runtime and add the regression test. Apache-2.0, 35.3k stars, maintainer: 'Just create a PR or an issue'.

What to contribute: docs/adoption/hunts/ntfy.md, a patch to web/src/app (Poller/Connection merge or AccountApi settings sync) with a Vitest unit test next to the existing *.test.js files and/or a web/e2e Playwright spec, an issue draft and a PR draft with AI-assistance disclosure.

Mechanism: README 'Contributing': create a PR or an issue; larger features need a Discord/Matrix check first; PR to binwiederhier/ntfy (main); build docs: https://ntfy.sh/docs/develop/

Frontend: web/ React (react-router 7, Vite on port 3000) with a hand-written data layer in web/src/app: Api.js, AccountApi.js, Poller.js, Connection.js (WebSocket), ConnectionManager.js, SubscriptionManager.js, db.js (IndexedDB).
